# 本机实时观战与服务生命周期

使用 Python 3.10+，macOS / Linux，无第三方依赖。`live_replay.py` 将已提交的规范化复盘 JSON 校验后，原子写入本局快照；浏览器通过仅监听 `127.0.0.1` 的临时 HTTP 服务轮询，不直接读取 `file://`。这不会自动收集子 Agent 回复：法官必须在实际推进时执行发布。

## 开局与恢复

先按 [replay-format.md](replay-format.md) 准备本局 `replay.json`，包含固定人物、规则，`records: []`、`chapters: []` 即可。只有真实结算后才添加 `winner`；不要预填赛后名单或回执。

下面 `<skill目录>`、`<对局目录>`、`<交付目录>` 是实际路径占位符。为每局建立独占的 `live` 目录；输入 JSON、原始日志和最终 HTML 放在该目录之外。

```bash
python3 <skill目录>/scripts/live_replay.py start \
  --directory <对局目录>/live --input <对局目录>/replay.json \
  --stage '人物入座，准备第一夜'
```

命令输出 `url`、`pid`。用可用浏览器工具打开该 URL，遵从用户的任务标签分组和工具约定；没有浏览器工具时提供可点击 URL。启动本身不擅自打开系统默认浏览器。

`server.json` 保存本局地址与随机控制令牌，`snapshot.json` 保存唯一对局 ID、修订号、运行状态、已提交复盘及渲染结果。保留它们供恢复与停止；不能发送给玩家，也不要公开托管。服务只允许观战页、脚本、快照、健康检查和受控停止，不提供目录浏览或法官原始日志。

已存在活跃服务时 `start` 拒绝重复启动，继续使用 `publish`。意外关闭后，以同一快照中的 `replay` 或与其一致/追加的输入重新 `start`，会保持对局 ID；重开输出 URL，因为端口可能变化。任务恢复时先核对原始 Agent 身份与记录，不因 HTTP 重启而重演对局。已完成目录不能重新开局。

## 每人完成后立即发布

公开对白（入座、警上、警下、PK、归票、狼队私聊）执行“一人实际回复 → 按权限传话 → 完整记录及来源事件 → publish成功 → 下一位”。下一发言者收到前面的最新原话。每条结束检查合法自爆，发生中断先处理规则，不继续旧队列。

```bash
python3 <skill目录>/scripts/live_replay.py publish \
  --directory <对局目录>/live --input <对局目录>/replay.json \
  --stage '第1天发言：当前座位已完成，下一位按警长指定方向' --received 1 --expected 12
```

独立投票也可逐人调用，并在每张完整票收到后立即publish；但投票材料全部取本轮冻结公开截止快照，不附此前锁票、理由和收票进度。票的actions用 `judge_private`、recipients仅本人，理由用 `private/review`；不能出现 `public` 或给队友转发私票。观众全知页可以实时看见私票，其他玩家不能访问页面或快照。状态栏显示“已锁7/12票，未向玩家公布”，不要写“已公开”。

全部有权票收齐才统一公告票型、票权、弃票、结果并publish；警长票权在放逐及放逐复投为1.5，选警为1。每张原始私票保留原范围，不改写为公开来源；统一公告另加法官 `all/summary` 事件。新局顶层必须写 `voting_mode: "sealed"`；此模式下渲染校验拒绝公开源投票或夹带public/team_message的锁票回复。旧局缺少此字段仍按实际历史渲染。

真实回复的全部内容字段一次提交，不先更新计数后扣正文。独立夜间能力也逐份发布，不等整夜；女巫只有仍有解药才能得到当晚刀口。警长竞选、退水、警徽传递、方向选择、遗言、技能、总结回执都按实际范围逐人追加。

章节只显示标题，当前阶段和等待状态放状态栏；不生成未实际传达的全知转场总结。发布的历史不可回填，重试幂等、文件锁、原子发布与终局关闭机制保持不变。

## 阅读体验

- 前台约每秒一次串行轮询；后台约每五秒请求一次，浏览器自身仍可能进一步限流。返回前台时立即同步最新完整快照。
- 增量追加，保留既有 DOM、阅读位置、来源展开状态和选中文本。阅读旧内容时显示“新增 X 条”，不强制跳到底部；“跟随最新”主动跳转并继续跟随。
- 首次打开保留在页面顶部，先看到人物与说明；实时页含私聊和真实身份标签的观众全知视角，头像昵称右侧显示真实角色；范围标签只表示实际传话对象，不意味着玩家见过角色标签。玩家只接收法官下发的材料，禁止访问观战数据。若用户要求无剧透公开观战，需另行实现服务端过滤，不能只隐藏页面元素。
- 显示连接状态、当前阶段、真实收取数量和法官最近发布时间。断连保留已读内容并重试，恢复后按 ID 去重；连接正常不等于法官已推进。

## 终局、离线导出与关闭

先结算所有技能与胜负，再向入选原 Agent 提供全局总结并收取感言，完成时间线和回执检查。运行：

```bash
python3 <skill目录>/scripts/live_replay.py finish \
  --directory <对局目录>/live --input <对局目录>/replay.json \
  --output <交付目录>/狼人杀复盘.html
```

`finish` 顺序执行：校验原文与已提交历史 → 原子生成自包含离线 HTML → 发布终局快照 → 最多等待 8 秒让观战页载入终局并确认 → 关闭本局 HTTP 服务并核验地址不再响应。重复同一 `finish` 可恢复离线输出并继续关闭服务。最终文件独立于临时状态目录，不引用 localhost 或外部脚本，服务关闭后仍能完整阅读。

已加载终局的实时页停止轮询，并保留最终内容及可在服务关闭后使用的离线下载按钮。后台、休眠或断连页面可能错过终局快照；**法官仍须在 `finish` 返回后用文件打开工具打开最终离线 HTML，并交付其绝对路径链接**，不把原临时 URL 当成永久复盘地址。确认命令输出“临时 HTTP 服务已关闭”；必要时用 `server.json` 的精确 URL 检查连接失败。

若校验/写文件失败，`finish` 不宣布完成，保留服务与旧快照供修复；修复后重试。若用户中止、无法继续、发生未恢复异常或即将结束任务且对局未完成，执行：

```bash
python3 <skill目录>/scripts/live_replay.py stop --directory <对局目录>/live
```

`stop` 可重复调用，保留原始日志和最后快照，不虚构终局或感言。只使用记录在本局元数据中的实例与控制令牌关闭服务，不根据 PID 直接杀进程，以免进程号复用误伤其他应用。停止失败须重试或明确报告具体服务地址与错误，不能说已清理。
